# SafeWatch Monitor 운영·보안 감사

- 감사일: 2026-08-07
- 범위: 0단계 기준선 확인 및 1단계 현황 감사
- 원칙: 코드에서 확인된 사실, 공식 정책에서 확인된 내용, 추가 확인이 필요한 판단을 구분한다.
- 이 문서는 법률 자문이나 서비스 이용 허가를 대신하지 않는다.

## 1. 기준선

- 작업 브랜치: `claude/cleanup-experimental-scripts`
- GitHub PR #13은 `main` 대상의 열린 PR이며, 감사 시점에는 병합되지 않았다.
- 감사 전에 존재하던 작업 트리 변경사항은 보존했다.
- 백엔드 독립 테스트 18개 파일, 프론트엔드 ESLint, Vite 빌드가 모두 통과했다.
- 0·1단계에서는 실행 로직, DB, 외부 서비스 설정을 변경하지 않았다.

## 2. 확인된 데이터 흐름

| 단계 | 처리 내용 | 개인정보·민감 가능 항목 |
|---|---|---|
| 수집 | 공식 API 또는 HTML 조회로 게시물 수집 | 제목, 원문, 작성자·닉네임, URL, 작성시각 |
| 저장 | Supabase의 수집·업로드·검수·실행 테이블에 저장 | 원문, 본문 전문, AI 결과, 대응 메모, 운영자명, Windows 계정, PC명 |
| AI 분석 | Gemini에 분류용 텍스트와 분류 기준 전송 | 게시물 텍스트, 부서명·키워드, 관련 공식 문서 |
| 검수 | 담당자가 판정과 대응상태를 확인·수정 | 재분류 사유, 담당자 기록 |
| 반출 | 엑셀 다운로드, 자동 저장, SMTP 첨부 | 원문 일부 또는 전체, URL, 판정, 부서, 대응상태 |
| 파기 | 자동 보존기간·삭제·익명화 기능 없음 | 저장 데이터와 생성 엑셀이 계속 남을 수 있음 |

일반 수집 분석은 제목·본문 일부를 Gemini에 보내지만, 엑셀 일괄 분석은 `original_text` 전체를 보낼 수 있다. 2차 검증은 조회한 본문 중 최대 3,000자를 보내며, Gemini 전송 전 개인정보 마스킹은 구현되어 있지 않다.

## 3. 위험도별 감사 결과

### 높음

1. **인증 없는 API와 네트워크 노출**
   - API에 로그인 또는 요청 인증이 없다.
   - 감사 당시 `backend/run_monitor.bat`은 Uvicorn을 `0.0.0.0:8001`로 실행했다. 2026-08-07 후속 변경에서 기본 바인딩을 `127.0.0.1:8001`로 제한했다.
   - 조회, 전체 엑셀 반출, 수집·분석 실행, 설정·문서·상태 변경 API도 같은 인증 없는 경계에 있다.
   - 담당자명·Windows 계정·PC명은 기록일 뿐 인증이나 부인방지 수단이 아니다.

2. **Gemini 전송 데이터 최소화 부족**
   - 엑셀 일괄 분석의 원문 길이 제한이 확인되지 않았다.
   - 감사 당시 전화번호·이메일·주민등록번호 형태·계좌번호 등의 사전 마스킹이 없었다.
   - 2026-08-07 후속 변경에서 수집 분석·2차 검증·엑셀 배치 분석의 최종 Gemini 프롬프트에 공통 마스킹을 적용했다.
   - 공개 게시물에도 닉네임, 병역, 건강·정신과, 정치적 의견이 포함될 수 있으므로 공개 여부만으로 저위험 데이터라고 볼 수 없다.

3. **대량 반출과 엑셀 수식 삽입 가능성**
   - 전체 게시물을 엑셀로 내보낼 수 있으며 인증이 없다.
   - 외부 입력이 `=`, `+`, `-`, `@`로 시작할 때 수식으로 해석되지 않도록 처리하는 방어가 확인되지 않았다.

### 중간

4. **보관·삭제 정책 미구현**
   - 수집 원문, 본문 전문, AI 결과, 검수·실행 이력, 생성 엑셀에 대한 자동 보관기간과 파기 절차가 없다.
   - 외부 게시물이 삭제·수정·비공개됐을 때 이를 반영하는 동기화가 없다.

5. **수집원 정책을 서버에서 충분히 강제하지 않음**
   - 현재 핵심 상태는 `is_active` 하나이며 정책 사유·확인일·검토 상태를 보존하지 않는다.
   - 회색 수집원 경고는 UI 중심이라 활성 상태인 소스를 API로 직접 실행하는 것을 별도 승인 절차로 막지 않는다.
   - 초기 마이그레이션의 `is_active` 기본값은 `true`이며 DCInside 초기 행은 이를 명시적으로 끄지 않는다. 실제 운영 DB의 현재 값은 별도 확인이 필요하다.

6. **업로드와 본문 조회의 입력 범위**
   - 감사 당시 업로드 파일 전체를 제한 없이 메모리로 읽었다. 2026-08-07 후속 변경에서 `.xlsx`, 10MB, 유효 데이터 1,000행으로 제한하고 압축 해제 크기와 내부 형식을 검증하도록 수정했다.
   - 언론사 등 임의 URL의 본문 추출 결과에 메뉴·광고·푸터가 섞일 수 있다.

7. **Excel 수식 삽입**
   - 감사 당시 외부 입력이 수식 시작 문자로 시작해도 그대로 셀에 기록됐다.
   - 2026-08-07 후속 변경에서 배치 결과, 수집 결과·메일 첨부, 자동 저장, 분기 보고서의 모든 문자열 셀을 일반 텍스트로 고정하도록 수정했다.

## 5. A/B 교대 운영에 대한 판단

복잡한 다중 역할 시스템은 현재 인원 규모만으로는 필요성이 확인되지 않았다. 앱 로그인을 두지 않으려면 최소한 다음 조건이 모두 충족되어야 한다.

- A와 B가 서로 다른 Windows 계정을 사용한다.
- 전용 PC에서만 실행하고 공용 계정·비밀번호를 공유하지 않는다.
- 서버를 loopback 또는 동등한 로컬 전용 경계로 제한한다.
- `.env`와 서비스 키에 대한 OS 파일 접근을 제한한다.
- 자리 이탈 시 화면을 잠근다.

LAN·다중 PC·서버 배포로 전환하거나 부인방지가 요구되면 요청 인증과 개인별 로그인이 필요하다. 기본 실행은 2026-08-07에 `127.0.0.1`로 제한했으며, 별도의 네트워크용 실행 설정은 제공하지 않는다.

## 6. 반영된 후속 순서

1. 운영 경계와 개선 요구사항 확정 — 코드 변경 없이 로컬 전용 조건, 데이터 처리 기준, 서비스별 상태를 결정한다.
2. 긴급 보안 보완 — 네트워크 경계, CORS, 업로드 제한, 엑셀 수식 삽입 방지는 완료했다. 위험 API 보호는 운영 형태가 바뀔 때 인증과 함께 재검토한다.
3. 개인정보·Gemini 전송 최소화 — 마스킹, 길이 제한, 작성자·본문 보관 범위를 처리한다.
4. 수집 소스 정책 통제 — `enabled/review_required/disabled`와 서버 강제를 마련한다.
5. 보관·삭제 기반 — 기간 설정, dry-run, 외부 삭제·비공개 동기화 구조를 마련한다.
6. AI 판정·알림 안전성 — 담당자 확인 원칙, 중복 발송과 경합을 검증한다.
7. A/B 운영·비밀정보·서비스별 정책을 문서화한다.
8. 전체 회귀·보안 검증 후 남은 위험을 보고한다.

보관기간, 닉네임 보존 여부, 알림 시점은 업무 결정 없이 임의로 확정하지 않는다. DB 마이그레이션 적용, 외부 서비스 활성화, 실제 삭제, 이메일 발송, 커밋·푸시는 각각 별도 승인을 받는다.

### 2026-08-07 사용자 결정

- Gemini 전송 길이 축소는 향후 결과 보고에서 정확도·비용·실제 이득을 분석한 뒤 결정한다. 현재 길이는 변경하지 않는다.
- 전화번호, 이메일, 주민등록번호 형태, 계좌번호 마스킹은 구현 완료했다.
- 작성자·닉네임의 미저장·가명화·출력 제외 여부는 보류한다.
- 본문 전문 보관, 이메일·엑셀 최소화, 수집원 정책, 보관·삭제, 알림 방식은 미결 작업으로 기록하고 다음 단계에서 하나씩 검토한다.

### 마스킹 범위와 한계

- DB에 저장된 원문은 변경하지 않고 Gemini 전송용 프롬프트만 마스킹한다.
- 전화번호, 이메일, 주민등록번호 형태, 구분자가 있는 10~16자리 계좌번호와 `계좌/계좌번호/입금계좌` 문맥의 연속 숫자를 가린다.
- 날짜, 점수 범위, 계좌 문맥이 없는 단순 일련번호는 오탐을 줄이기 위해 유지한다.
- 작성자명·닉네임·주소·자유서술 속 병역·건강·정치적 의견은 자동 마스킹하지 않는다. 따라서 개인정보 위험이 모두 제거된 것은 아니다.

## 7. 아직 확인이 필요한 사항

- 운영 PC 방화벽과 실제 네트워크에서 8001 포트에 접근 가능한 범위
- 실제 Supabase 운영 DB의 RLS·정책과 현재 수집원별 `is_active` 값
- 각 외부 API 애플리케이션의 승인 상태와 등록된 이용 목적
- 작성자·닉네임과 원문 전문이 실제 업무·감사에 필요한 범위
- 데이터 및 생성 엑셀의 보관기간
- 자동 알림 시점과 최종 승인 절차
- FMKorea 및 본문 직접 조회 대상 도메인의 공식 정책 원문
