## 2. 모니터 기준 구조 문제 (우선순위)

### 1순위 — 두 시스템의 분류 스키마 분기
같은 병무청 업무인데 산출 필드가 갈라져 있다.

| | 모니터 | 분류자 |
|---|---|---|
| 분류축 | `label_l2`(병무청 7분류), `subject` | `intent_type`, `content_type`, `action_type`, `category` |
| 부서 | `department_id` (1개) | `department_id`, `department_id_2` (2개) |
| 실패추적 | 없음 (NULL 유지) | `status`, `error_reason` |

→ **이대로면 두 시스템 결과를 합산한 분기 보고서를 만들 수 없다.** 데이터가 쌓일수록
사후 정합 비용이 커진다. 어느 쪽 스키마로 통일할지가 다른 모든 항목의 선행 조건.

### 2순위 — 재분류 + 이력 (Q3) · 양쪽 다 없음
문서가 명시적으로 "필요하다"고 답한 기능인데 두 시스템 모두 공백.
AI 결과를 담당자가 뒤집은 기록이 남지 않으면 삭제 요청의 **근거 추적이 불가능**하다.
공공기관 감사 관점에서 가장 약한 고리.

### 3순위 — 삭제 요청 선정 워크플로 화면 (Q1)
시스템의 존재 이유. 모니터에 백엔드(`response_status` + PATCH API)가 이미 있고
**화면만 없다** → 투입 대비 효과가 가장 좋다.

### 4순위 — 배포·인증·동시성 (R9 + Q2)
외부망 공개가 실제 계획이면 1순위로 올라간다. 현재:
- 모니터: 개인 PC `.bat` 로컬 실행, 인증 없음, 전역 단일 상태(4명 동시 사용 불가)
- 분류자: 인증 없음

### 5순위 — 복수 부서(Q4) · 의도/내용 유형(R7)
**분류자엔 이미 있음.** 모니터에도 필요한지는 1순위(스키마 통일) 결정에 종속된다.
단독으로 먼저 손댈 항목이 아니다.

## 3. 상충 1건 — Q7 (출처별 동일 기준)

문서: *"언론, SNS, 커뮤니티, 유튜브 등 출처별로 판단 기준이나 판단 방식은 동일하게 적용"*

모니터 현황:
- `keyword_scorer.py` — 일반 임계치 2, **언론만 4** (`NEWS_PREFILTER_THRESHOLD`)
- `analyzer.py:123` — Gemini 프롬프트에 출처 라벨 주입

판단 로직 자체는 동일하나 **출처에 따라 AI 판단을 받는 대상 범위가 달라진다.**
비용 최적화 목적으로 사용자가 명시 지시한 사항이며, 근거는 언론 라벨 데이터 170건에서
중간·높음의 최소 키워드 점수가 4였다는 점. 유지하더라도 **감사 대비로 근거를 SPEC에 남길 것.**

## 5. 사용자 결정 필요

1. **스키마 통일 방향** — 모니터를 분류자 축(의도/내용 유형)에 맞출 것인가,
   분류자를 병무청 공식 7분류로 옮길 것인가, 아니면 둘 다 유지하고 매핑 테이블을 둘 것인가
2. **납품 대상** — 사이버조사과 요구사항의 납품 시스템은 분류자인가, 모니터인가, 통합본인가
3. **외부망 배포 여부** — Yes면 인증·동시성이 최우선
4. **Q7 유지 여부** — 언론 임계치 완화를 유지할지, 문서대로 동일 적용으로 되돌릴지
