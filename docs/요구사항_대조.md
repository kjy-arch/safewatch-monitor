# 사이버조사과 요구사항 ↔ 구현 대조

- **원본**: `개발자가 사용자에게 문의하는 질문사항(사이버조사과).hwpx` ('26.7.22, 요구사항 20건)
- **최초 작성**: 2026-08-04 (통합 전) · **갱신**: 2026-08-07 (§3 결함 표에 난독화 누락 경로 추가)
- **대상**: `safewatch-monitor` 통합본 — 분류자(safewatch-classifier)를 흡수한 단일 시스템

> **이력**: 최초 작성 시점에는 요구사항이 분류자에만 반영돼 있고 모니터에는 없어,
> 두 시스템의 분류 스키마가 갈라져 합산 보고서를 만들 수 없는 상태였다.
> 이후 분류자를 모니터로 흡수해 통합본을 만들면서 대부분이 해소됐다.

## 2. 남은 항목

### Q6 — 1년 보관 + 아카이빙 (미구현)
데이터가 쌓이기 전이라 시급하지 않으나, 운영 1년차에는 필요해진다.
필요 작업: 보관 기간 정책 결정 → 아카이브 테이블 또는 엑셀 덤프 → 정기 실행.

### Q2·R9 — 인증과 배포 형태 (사용자 결정)
현재는 **담당자 PC에 설치**하고 각 PC가 같은 Supabase를 본다. 하루 1명씩 교대하는
운영 방식에서는 충분하지만, 아래 경우 **로그인 도입이 필요**하다.

- 서버 1대에 올려 여러 명이 접속하는 방식으로 바꿀 때
  (실행 이력의 Windows 계정이 전원 "서버 계정"으로 찍혀 무의미해진다)
- 감사에서 **부인방지**가 요구될 때 (현재 신원 기록은 위조 가능)

### 화면 빌드 의존성
`frontend/dist`는 `.gitignore` 대상이라 git으로 받은 PC에는 없다.
**Node.js가 없으면 구형 단일 HTML로 폴백**되어 보고서·실행이력·검수 화면을 쓸 수 없다.
Node 설치가 불가한 PC가 있으면 `dist`를 저장소에 커밋하는 방식으로 바꿔야 한다.

## 3. 통합 과정에서 잡은 결함

요구사항 대조와 별개로, 검증 중 발견해 고친 실제 버그들.

| 결함 | 영향 | 조치 |
|---|---|---|
| 엑셀 원문 열로 **제목을 선택** (별칭 목록이 set이라 순회 순서가 임의) | 본문이 통째로 분류에서 빠짐. 같은 글이 `단순문의/비대상` → 실제로는 `방법문의/삭제대상` | 우선순위를 튜플로 고정, 제목은 최후순위 |
| 통합 프롬프트 1차 시도에서 **무관한 글을 병역 맥락으로 해석** | 「해당없음」 정확도 0.71 → 0.29 | 관련성 게이트를 프롬프트 맨 앞에 배치 |
| 배치 경로에 **JSON 강제 옵션 누락** | 응답 2건이 조용히 유실 | `response_mime_type` 지정 |
| 분기 보고서가 **업로드분만 집계** | 수집분 전체 누락 | 통합 조회로 교체 |
| 통합 시 **같은 글 이중 계상** (수집 엑셀 재업로드분) | 실측 296건 중복 | 원문 앞 60자 대조로 제거 |
| 보고서 부서별 집계가 **1순위 부서만** 계상 | 복수 부서 매칭(Q4)이 보고서에 미반영 | 소관 부서마다 계상 |
| 손상 배치(연번 숫자를 원문으로 분류) 316행 | 전량 「해당없음」으로 통계 왜곡 | 삭제 |
| `keyword_scores.json` 누락 시 **사전필터가 조용히 비활성** | 다른 PC에서 전건 Gemini 호출 → 비용 급증 | 설치 절차에 생성 단계 추가 + `/api/health`에 상태 노출 |
| 게이트·사전필터가 **원문만 비교**해 난독화 글을 놓침 (2026-08-07) | `병.역.면.제`·`병 역 면 제`·zero-width 삽입 글이 게이트를 못 넘고 `비대상`으로 자동 확정 → **Gemini에 가지 않고 삭제요청 선정에서 누락.** 조장 게시물이 난독화를 가장 많이 쓰는 집단이라 영향이 크다 | 원문 ∪ `normalize()` ∪ `compact()` 합집합 매칭(`text_normalize.py`). 적용 범위는 실데이터 1,485건 측정으로 결정 — 게이트 전 용어 / 사전 3음절 이상. 상세 [SPEC.md](../SPEC.md) §10 |
| **정치 비판을 삭제대상으로 오판** (2026-08-07) | 삭제대상 38건 중 **27건(71%)이 정치인 병역 논란 유튜브 댓글**. 축 B의 `편법·속임수·공정성 훼손`("병무행정 신뢰도 훼손")이 `정책비판`을 삼켰고, **6건은 Gemini가 `풍자/비판`이라 판정했는데도** 결정적 매핑이 삭제대상을 확정. 공공기관이 정치 비판을 삭제 요청 후보로 올리는 결과 | 프롬프트 경계 한정 + 정치 비판 사례 3종 추가 + 파서 안전망(`풍자/비판`+`삭제대상` → `종합판단` 강등). **알림 오발송도 함께 차단**(강등하면 `DELETE_SCORE_FLOOR` 67이 안 걸린다) |
| 수집이 **검색 API 요약(약 120자)만 저장** (2026-08-07) | 지식인 본문 중앙값 128자, 삭제대상 38건 전부 200자 미만. 요약만 보고 브로커로 판정한 글의 전문이 병무용 진단서 제도 안내였고 "전화번호"는 **지방병무청 상담번호 14개 목록**이었다 | 삭제대상·종합판단만 본문을 재조회해 2차 판정(`fulltext.py`·`verify.py`, 마이그레이션 010). **원 판정을 덮어쓰지 않고** 검수 화면에 나란히 표시. 누락 규모는 `estimate_snippet_miss.py`로 표본 추정 |
