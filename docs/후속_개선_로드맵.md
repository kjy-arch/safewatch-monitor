# SafeWatch 후속 개선 로드맵

- 작성일: 2026-08-08
- 상태: 성과지표 화면 이후 검토
- 원칙: 발표 전에는 신규 범위를 확대하지 않고 현재 기능 안정화에 집중

## 1. 보관·아카이빙 정책

요구사항 20건 중 남은 미구현 항목이다.

- 원문·본문 전문·AI 결과·검수 이력·실행 이력의 보관기간 결정
- 생성 엑셀과 이메일 첨부파일의 파기 기준 결정
- 실제 삭제 전 대상과 건수를 보여주는 dry-run
- 관리자 확인 후 파기
- 파기 결과와 실패 건 감사 이력
- 기간은 코드에 고정하지 않고 업무·법무·정보보안 검토 후 설정

## 2. 제외 규칙 운영 보강

현재는 URL 완전일치와 정규화한 내용 완전일치만 제공한다.

- 규칙별 누적 적중 건수·최근 적중일
- 등록자·등록 사유·등록일 상세
- 활성·해제 규칙 통합 검색
- 규칙 목록 백업·내보내기
- 잘못 등록한 규칙의 영향 범위 확인

부분문자열·AI 유사도 자동 제외는 정상 글 누락 위험이 있어 운영 데이터로 안전성이
확인되기 전에는 도입하지 않는다.

## 3. 수집원 정책 강제

- 수집원 상태: `허용 | 검토 중 | 비활성`
- 정책·법무 검토 사유, 승인자, 승인일 기록
- 화면 선택뿐 아니라 서버 API에서도 미승인 수집원 실행 차단
- 디시·에펨·인스타·X·틱톡 및 렌더링 페이지 본문 조회의 정책 상태 관리
- 정책 변경 시 운영자에게 영향 범위 표시

공식 API가 아닌 수집원은 검토 완료 전 확대하지 않는다.

## 4. 인증·접근통제

현재 `127.0.0.1` 로컬 전용 운영에서는 후순위다. 여러 PC나 내부망 서버로 전환할 때
최우선 과제로 승격한다.

- 사용자 로그인
- 관리자·검수자·조회자 권한 분리
- 엑셀 반출·설정 변경·제외 규칙 등록/해제 권한
- 사용자 ID 기반 감사 로그
- 세션 만료·비밀번호 또는 기관 인증 연계
- 인증 없는 기존 API 차단

## 5. 착수 순서

1. 성과지표 화면 운영 검증
2. 보관·아카이빙 정책 결정 및 구현
3. 제외 규칙 운영 보강
4. 수집원 정책 강제
5. 서버 전환이 결정되면 인증·접근통제
