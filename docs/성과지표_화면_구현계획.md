# SafeWatch 성과지표 화면 구현 계획

- 작성일: 2026-08-08
- 목적: 발표용 수치를 수작업으로 계산하지 않고, 실제 운영 결과와 비용 절감을 같은 기준으로 확인
- 원칙: `false_reason` 문자열이나 화면 표시값을 세지 않고 구조화된 필드·이력만 집계

## 1. 화면에서 답할 질문

1. 얼마나 수집했고, 그중 실제 검토 가치가 있는 글은 몇 건인가?
2. Gemini를 호출하지 않고 처리한 건은 몇 건인가?
3. 1차 판정을 본문으로 다시 확인해 몇 건을 바로잡았는가?
4. 담당자가 최종적으로 뒤집은 판정은 몇 건인가?
5. 제외 규칙이 반복 업무와 AI 호출을 얼마나 줄였는가?
6. 출처별로 헛읽기가 많은 곳은 어디인가?

## 2. 지표 정의

| 지표 | 정의 | 데이터 근거 |
|---|---|---|
| 수집 건수 | 기간 내 `crawled_articles` 생성 건수 | `created_at` |
| 업로드 건수 | 기간 내 `articles` 생성 건수 | `created_at` |
| Gemini 호출 건수 | `analysis_method=gemini` 성공 건수 | 신규 구조화 필드·이력 |
| 로컬 처리 건수 | 관련성 게이트·사전필터 처리 건수 | `analysis_method` |
| 제외 규칙 적중 | URL·동일 내용 규칙 적중 건수 | `exclusion_matches` |
| AI 호출 절감률 | `(게이트+사전필터+제외) / 전체 분석 완료` | 위 구조화 필드 |
| 2차 판정 변경률 | `verify_action != action_type` / 확인완료 | `verify_*` |
| 담당자 재분류율 | 담당자가 판정 필드를 변경한 고유 글 / 검수 글 | `reclassify_logs` |
| 최종 삭제대상 | 담당자 판정 반영 후 삭제대상인 글 | `action_type`, 대응상태 |
| 출처별 무관율 | `category=해당없음` / 출처별 분석 완료 | 분류 결과 |
| 토큰 사용량 | Gemini 응답의 입력·출력 토큰 합계 | `usage_metadata` 신규 기록 |
| 예상 비용 | 토큰 사용량 × 관리자가 입력한 단가 | 단가 설정 + 토큰 이력 |

### 표시 주의

- 마이그레이션 적용 전 과거 데이터는 `분류경로 미상`으로 표시한다.
- 예상 비용은 실제 청구액으로 표현하지 않고 **설정 단가 기준 추정치**라고 명시한다.
- 재분류 이력은 필드 변경 행 수가 아니라 고유 글 수로 센다.
- 복수 부서 건수는 전체 건수와 분리한다.

## 3. 데이터 설계

### 3.1 마이그레이션 012

`crawled_articles`와 `articles`에 다음 필드를 추가한다.

- `analysis_method`: `gemini | relevance_gate | prefilter | exclusion`
- `analyzed_at`: 실제 분석 완료 시각

Gemini 사용량은 별도 `ai_usage_logs`에 기록한다.

- 대상 테이블·대상 ID
- 실행 유형: 수집분·업로드분·2단계 검증
- 모델명
- 입력 토큰·출력 토큰·총 토큰
- 성공 여부·실패 유형
- 호출 시각

원문·프롬프트·응답 전문은 사용량 이력에 중복 저장하지 않는다.

### 3.2 기존 이력 활용

- `exclusion_matches`: 제외 규칙 적중
- `reclassify_logs`: 담당자 재분류
- `run_logs`: 실행 횟수·처리량·실패
- `verify_*`: 1차·2차 판정 비교

## 4. 백엔드 구현

1. 수집·업로드·2단계 검증 경로에 분석 방법과 토큰 기록 추가
2. 기간 집계 서비스 `services/metrics.py` 작성
3. `GET /api/metrics/summary?from=YYYY-MM-DD&to=YYYY-MM-DD` 추가
4. 출처별 상세 집계와 전체 요약을 한 응답으로 반환
5. 날짜는 KST 기준으로 받고 DB 조회는 UTC 경계로 변환
6. 집계 실패 시 일부 숫자를 0으로 숨기지 않고 오류를 표시

## 5. 화면 구성

기존 「보고서」 화면 상단에 `운영 성과` 영역을 추가한다.

### 1행 — 핵심 숫자

- 전체 처리
- Gemini 호출
- AI 호출 절감률
- 최종 삭제대상

### 2행 — 품질·안전

- 2차 판정 변경률
- 담당자 재분류율
- 제외 규칙 적중
- 조회·분석 실패

### 하단 — 출처 비교

- 출처별 수집 건수
- 출처별 무관율
- 출처별 최종 삭제대상

차트는 장식보다 비교가 쉬운 가로 막대 하나만 사용하고, 나머지는 숫자와 표로 구성한다.

## 6. 구현 순서

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| 1 | 지표 정의·012 스키마 확정 | 각 숫자의 분자·분모·기간 기준이 문서화됨 |
| 2 | 분석 방법·토큰 기록 | 신규 처리 건에 누락 없이 기록됨 |
| 3 | 집계 API | 테스트 데이터 수기 계산과 API 결과 일치 |
| 4 | 보고서 화면 | 날짜 변경 시 모든 카드·표가 같은 기간으로 갱신 |
| 5 | 운영 검증 | 실제 1일분과 DB 원자료 대조 완료 |
| 6 | 발표 수치 확정 | 화면 수치와 발표자료 수치가 일치 |

## 7. 테스트·검수 기준

- KST 날짜 경계(00:00) 테스트
- 데이터 없음·일부 실패·과거 미상 데이터 테스트
- 같은 글의 재분류 로그가 여러 행이어도 고유 글 1건으로 집계
- 제외 규칙 적중과 사전필터를 중복 절감으로 세지 않음
- 1차·2차 판정 변경률 분모는 `확인완료`만 사용
- 수식·집계 결과를 실데이터 표본 20건 이상과 대조
- 기존 테스트 전체, 프론트 lint·build 통과
